CAREFLOW – PATIENT JOURNEY PROCESS DISCOVERY REPORT
==========================================================

Method
This report derives a directly-follows graph (DFG) from the cleaned event log.
Events are ordered by case ID, timestamp, and event ID. Each edge count records
how often one activity is immediately followed by another across all cases.
This is a data-derived process model; PM4Py was not installed in this runtime,
so PM4Py's discovery API was not executed or validated.

Interpretation
The dominant pathway starts with Registration followed by Triage and Doctor
Consultation. Diagnostic steps (Laboratory Test and X-Ray) commonly lead back
to Doctor Consultation, after which cases may proceed to Treatment and Discharge.
Some cases contain repeated triage or consultation events. These loops are
observable workflow patterns, not proof of unnecessary care or inefficiency.

Limitations
- The graph represents directly-following transitions, not a clinical guideline.
- Transition counts are event-log observations and may include repeated edges
  within a case.
- No conformance score or bottleneck diagnosis is claimed in this report.
- Timing/waiting-time analysis is not included in this process model.
- Validate the model with PM4Py in the project environment before describing
  it as PM4Py-discovered.
